# nim-agents

Shared composition layer over ACP and Agent Harbor.

Commands:
- `just build`: compile native and JS targets.
- `just test`: run native and JS tests.
- `just lint`: run Nim and Nix checks.
- `just format`: format Nim and Nix sources.

Structure:
- `src/nim_agents/client.nim`: common prompt/session abstraction.
- `tests/test_consumers.nim`: direct IsoNim Editor and CodeTracer-style import smoke tests.
- `src/nim_agents/activity_groups.nim`: a session's activity as a cardless timeline over `ActivityTimeline` (`TimelineFold`): items, groups of similar consecutive events and their break rules, gap and turn lines, running items on a group line, level-2 details and command traces, and the chunk and operator-input policies. The grouping rules live there and nowhere else; its node ids are stable, and `nodesOf` is the closed form the fold is checked against. `tests/test_activity_groups.nim` tests it natively and under JS.
- `src/nim_agents/instruction_composer.nim`: the omnibox composer's domain (`ComposerDraft`): an instruction, the context the window offers, the routing agent's decision (three destinations in one fixed order: the window's session, a manager agent, a UI action; what it cites, never an excluded chip or a note), redirects before and after sending, deliveries and the `Recent` record, and the launch, schedule (`validateCron`) and new-initiative forms' validation. `tests/test_instruction_composer.nim` tests it natively and under JS.
- `src/nim_agents/result_commands.nim`: the omnibox's result commands: what the field's text asks for (`/s`, `/ah`, `/ah-<id>`, `/ah<alias>`, an instruction's `@` and `/` sigils), Agent Harbor's input-command discovery and results in their documented shapes, a search over every provider (`ResultSearch`: supersession by query generation, the providers' order, failures, the eight-row limit), completions, where opening a row goes, and the launcher's abilities each reached by a route. `tests/test_result_commands.nim` tests it natively and under JS.
- `src/nim_agents/agent_harbor/`: the Agent Harbor front-end domain, signal-free and app-agnostic: `fleet_records` (wire records), `session_directory` (the sessions a front-end knows, its lifecycle reducer, its per-event step `applyEvent` over `foldEvent`, and its policies: effective status, order, label sources), `activity_words` (the one-line wording of a session event, which every view of an event uses), `activity_digest`, `session_replay` (a session at a moment of its history, and the per-event step `foldEvent` it repeats), `fleet_fold` (a fleet list that follows lifecycle frames, listing entries and session events after its first listing, recomputing digests and counts; `applyFleetFrame` folds the same frames into a plain `SessionDirectory`), `initiatives` (plans parsed as Agent Harbor's server parses them, progress events; `parseMilestoneHeading` is the one milestone-heading rule), `review_record` (a plan's review record: spec changes with their approval grammar, verification entries by leading token, implementation details, key source files; tiers 1 and 2 read from the change's diff; the Changes panel's tabs), `change_diff` (`git diff` text as files and hunks, committed and uncommitted joined relative to the merge base, key files first, filters, the summary and roll-up lines), `inbox` (the inbox in the server's order, its stream reducer that never re-sorts, the Next/Prev cursor rule a stand-in source keeps, chips, item pages and the answer form's rules), `operator_actions` (the operator's writes as typed values with their routes; a password is a `Secret` that is never printed). `activity_words.waitWords` is the one wording of what a waiting session asks of the operator, shared by inbox rows (`inbox.kindWord`) and tab tooltips (`session_directory.waitKindWord`). Import the modules explicitly; `tests/test_agent_harbor_domain.nim`, `tests/test_agent_harbor_fleet_fold.nim`, `tests/test_review_record.nim`, `tests/test_change_diff.nim` and `tests/test_inbox.nim` test them natively and under JS. Choices front-ends make differently are policies here, never one fixed rule; IsoNim viewmodels over them live in nim-agents-isonim-viewmodels.

This repo re-exports lower-level ACP and Agent Harbor surfaces for advanced callers.
